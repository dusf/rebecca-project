# 即时通讯配置页设计规格

**日期：** 2026-08-03  
**状态：** 已确认方案 A，待规格评审  
**范围：** 后台「配置 > 即时通讯」可交互原型；不调用第三方接口、不注入真实买家端脚本。

## 目标与边界

商家可在一个配置页内选择并连接一个第三方即时通讯服务商（首批展示及时语、Salesmartly 和“更多服务商”），再控制买家端聊天入口的启用状态与展示方式。买家端同一时刻只允许一个聊天入口，避免多服务商悬浮按钮重叠或争夺会话。

本期是原型：连接、测试与保存均在本地原型数据中模拟，不请求或保存真实 API 密钥、安装代码或买家信息。

## 信息架构与交互

页面沿用现有配置页的左侧菜单和右侧设置面板。点击「即时通讯」后显示以下三个区块：

1. **服务商连接**
   - 卡片展示及时语、Salesmartly 和更多服务商。
   - 卡片显示未连接、已连接、当前启用三种状态；每张卡片带服务用途与“连接/管理”操作。
   - 同一店铺只可设定一个当前启用服务商。切换服务商前保留原连接配置，但买家端只渲染新启用服务商。
   - 选择未连接服务商时展开连接配置：工作区地址、应用标识、买家端安装标识。原型中的“测试连接”只校验必填项并显示模拟成功状态。

2. **买家端展示**
   - 总开关控制是否在买家端显示聊天入口；未有已连接服务商时禁用开关，并显示原因。
   - 配置入口位置（右下/左下）、展示设备（桌面端/移动端）及入口文案（例如“在线咨询”）。
   - 右侧提供静态店铺缩略预览；配置变化即时反映聊天气泡的位置、服务商品牌缩写和入口文案。

3. **接入说明与保存**
   - 明确说明：正式接入时，服务端仅在符合展示范围的买家端页面加载当前服务商的官方脚本；密钥只保存在服务端，不下发到浏览器。
   - 页脚提供重置与保存。保存后在浏览器顶部显示成功提示；保存状态写入 `currentShop.settings.messaging` 的原型数据。

## 数据模型（原型）

```js
{
  provider: 'jishi' | 'salesmartly' | '',
  connections: {
    jishi: { connected: false, workspace: '', appId: '', installId: '' },
    salesmartly: { connected: false, workspace: '', appId: '', installId: '' }
  },
  display: {
    enabled: false,
    position: 'right',
    desktop: true,
    mobile: true,
    launcherText: '在线咨询'
  }
}
```

原型只存演示字段。正式接入时，连接凭据迁移到服务端密钥存储；前端只读取连接状态、服务商名称和允许展示的安全配置。

## 正式买家端集成路径

1. 商家在后台授权并由服务端验证服务商凭据。
2. 服务端保存加密凭据和当前启用服务商，并返回非敏感展示配置。
3. 买家端布局在页面加载时读取展示配置；仅当总开关、设备范围和页面范围均允许时，加载当前服务商的官方 SDK。
4. 切换或停用服务商时，服务端停止下发旧 SDK；买家端只保留一个官方入口。

## 状态与可用性

- 空状态：没有连接服务商时，展示选择提示，买家端总开关禁用。
- 成功状态：测试连接成功后卡片更新为“已连接”，可启用买家端展示。
- 失败状态：必填项缺失时在字段下显示简短错误，不改变当前启用配置。
- 响应式：桌面端为配置区与预览区双列；窄屏改为单列，预览移动到展示设置之后。
- 可访问性：卡片、开关、位置选项和保存按钮均可键盘聚焦；状态采用可读文本而非仅依赖颜色。

## 验收标准

- 即时通讯菜单不再显示“正在建设”，而是显示三个完整配置区块。
- 及时语与 Salesmartly 可在原型中切换、模拟连接并保存状态。
- 未连接时不能开启买家端入口；连接后可配置位置、设备和入口文案。
- 预览实时呈现唯一聊天入口，切换服务商或位置后立即更新。
- 所有可见下拉、开关和浮层均复用现有共享组件，并以运行时组件完成验证。
